# 0001. Pi は記録のみを担い、変換・合成は Mac で行う

## ステータス

承認

## コンテキスト

pivr180 は Raspberry Pi 5 に HQ Camera（IMX477）×2 と 190° 魚眼レンズ（Entaniya RP-L190HQ）×2 を載せ、Meta Quest 3 で見られる VR180 写真を撮るデバイスである（[plan.md](../plan.md)、[device_specs.md](../device_specs.md)）。

魚眼画像から SBS 正距円筒 180° への変換や左右の補正は計算量が大きく、補正パラメータの手動調整も必要になる。どの処理をデバイス（Pi）で行い、どの処理を Mac で行うかを決める必要がある。

なお、Raspberry Pi 5 にはハードウェア H.264 エンコーダが搭載されていない。後続で動画を扱う場合もエンコードは CPU 負荷となる。

## 決定

- Pi（device）は撮影・記録のみを行う。左右の JPEG と meta.json を NVMe に保存する。
- 変換・合成・補正は Mac（editor）で行う。Mac は Pi から rsync（SSH）で取り込む。

## 検討した選択肢

### Pi で全処理

- 利点: デバイス単体で VR180 画像まで完結し、Mac が不要になる。
- 欠点: Pi の CPU 負荷・発熱・バッテリー消費が増え、撮影間隔に影響する。補正値の手動調整をデバイス上で行う UI が必要になる。ハードウェア H.264 エンコーダがないため、後続の動画対応で更に不利になる。

### Pi で撮影後バックグラウンド変換

- 利点: 撮影操作は妨げずに、デバイス単体で変換結果を得られる。
- 欠点: バックグラウンドでも CPU 負荷・発熱・電力消費は残る。補正値を後から調整する場合は結局再変換が必要になる。

### Pi は記録のみ、変換・合成は Mac（採用）

- 利点: Pi の処理を単純に保て、撮影の応答性と電力に有利。変換は高性能な Mac で行え、補正値の調整と再変換を繰り返しやすい。
- 欠点: 変換結果を得るには Mac への取り込みが必要で、デバイス単体では完結しない。

## 結果 / 影響

- device は撮影・記録・取り込み用の公開に専念でき、実装とテストが単純になる。
- editor（Mac）に取り込み・補正・変換・viewer 配信の責務が集中する。
- 撮影現場で VR180 の仕上がりを確認できないトレードオフを受け入れる。現場での確認はスマホ Web UI の左右並びライブプレビューと撮影一覧で補う。
