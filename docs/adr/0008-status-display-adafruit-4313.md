# 0008. 状態表示は SPI ディスプレイ（Adafruit 4313）で行う

## ステータス

承認

## コンテキスト

pivr180 は、スマホを使わずにシャッターボタンだけで撮影できるようにする（[plan.md](../plan.md) の物理 UI、[milestone.md](../milestone.md) の M3）。そのため、待機中・撮影中・エラーといった状態を本体で知らせる手段が必要になる。

当初は GPIO につないだ状態 LED で知らせる計画だった（#20）。しかし LED は手元になく、代わりに Adafruit 1.3" 240x240 Wide Angle TFT LCD Display with MicroSD - ST7789（[Product ID 4313](https://www.adafruit.com/product/4313)）を所有している（#77）。

Adafruit 4313 の仕様は次のとおり。

- 1.3" IPS TFT、240×240、16 bit カラー
- コントローラは ST7789 で、4 線式 SPI で接続する
- 3.3V レギュレーターと 3/5V レベルシフターを搭載する
- 1×16 のピンヘッダーと 18 ピンの EYESPI FPC コネクタを持つ
- microSD スロットを持つ
- 外形 35.8 × 35.8 × 5.3 mm、取り付け穴 2.5 mm ×4（穴の間隔 33 × 30 mm）
- Adafruit が Pillow の画像を描画できる Python ライブラリ（Adafruit_CircuitPython_RGB_Display、Blinka 経由）を提供している

カメラは CSI、NVMe 拡張ボードは PCIe の FFC で接続するため、GPIO ヘッダーは使っていない。

## 決定

- 状態表示には **Adafruit 4313** を使い、待機中・撮影中・エラーを表示する。エラー時は内容を短い文字で表示する。
- ディスプレイは SPI0 と、DC・RST 用の GPIO で接続する。表示は Pillow で描画し、SPI で転送する。
  - ライブラリは Adafruit_CircuitPython_RGB_Display（Blinka）を使う。Pi 5 で Blinka が動作するかは実機で確認し、動作しなければ ST7789 に対応する luma.lcd を使う。
- シャッターボタンは引き続き GPIO につなぎ、gpiozero で扱う。
- GPIO ピンの割り当ては M8-4（#46）で決める。
- ディスプレイの microSD スロットは使わない。

## 検討した選択肢

### GPIO の LED と抵抗を購入する

- 利点: 部品が安く、gpiozero で扱える。当初の計画をそのまま使える。
- 欠点: 部品を追加で購入する必要がある。点灯・消灯・点滅でしか状態を区別できず、エラーの内容は示せない。

### Pi 5 の基板 LED（ACT/PWR）を使う

- 利点: 部品を追加する必要がない。
- 欠点: gpiozero ではなく `/sys/class/leds` 経由で制御するため、root 権限か udev の設定が必要になる。筐体の内側に隠れるため、ライトパイプが必要になる。2 色しかなく、表せる状態が少ない。

### SPI ディスプレイ Adafruit 4313 を使う（採用）

- 利点: 手持ちの部品で済む。状態に加えて、エラーの内容を短い文字で表示できる。
- 欠点: SPI0 と DC・RST 用の GPIO を使うため、配線が増える。筐体に表示窓と固定部が必要になる。撮影ソフトが起動するまでは何も表示されない。

## 結果 / 影響

- 部品を追加で購入せずに状態を表示でき、エラーの原因を本体だけで把握できる。
- 配線図（M8-4）は、シャッターボタンに加えてディスプレイの SPI0・DC・RST のピンを扱う。
- 筐体は、ディスプレイの表示窓と、取り付け穴を使った固定部を設ける必要がある（[0007](./0007-blender-enclosure-fdm-printing.md)）。
- 撮影ソフトが起動するまでは何も表示されない。電源が入っていることは Pi 5 の基板の電源 LED で確認する。
- Pi 5 で Blinka が動作しないリスクがある。実機で確認し、動作しなければ luma.lcd に切り替える。
