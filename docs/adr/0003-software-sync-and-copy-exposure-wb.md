# 0003. 左右カメラはソフトウェア同期とし、露出/WB は左カメラの値を右へコピーして固定する

## ステータス

承認

## コンテキスト

VR180 の立体視では、左右のカメラが同じ瞬間を撮影し、明るさ・色が揃っていることが重要である。左右のずれは被写体の動きによる視差の破綻や、目による明るさ・色の違いとして現れる。

HQ Camera（IMX477）×2 を Raspberry Pi 5 の 2 つのカメラコネクタに接続し、Picamera2 で制御する（[plan.md](../plan.md)、[device_specs.md](../device_specs.md)）。左右の撮影タイミングの同期方法と、露出/ホワイトバランス（WB）の揃え方を決める必要がある。

## 決定

- 同期: **ソフトウェア同期**とする。libcamera のカメラ同期機能を使い、センサータイムスタンプを照合する。左右のセンサー時刻と差分を meta.json に記録する。
- 露出/WB: 左カメラで AE/AWB を行い、得られた ExposureTime / AnalogueGain / ColourGains を右カメラへコピーして固定する。

## 検討した選択肢

### 同期方式: XVS ハードウェア同期

- 利点: センサーレベルで厳密にフレームを同期できる。
- 欠点: カメラ基板の改造が必要で、作業の難易度と破損リスクが高い。

### 同期方式: 同期なし

- 利点: 実装が最も単純。
- 欠点: 左右の撮影時刻がずれ、動く被写体で立体視が破綻しうる。ずれの大きさも把握できない。

### 同期方式: ソフトウェア同期（libcamera camera sync ＋ センサータイムスタンプ照合）（採用）

- 利点: 基板改造なしで左右の撮影タイミングを揃えられる。差分を meta.json に記録するため、ずれを定量的に把握できる。
- 欠点: ハードウェア同期ほど厳密ではない。

### 露出/WB: 各自 AE/AWB で Mac 側で色合わせ

- 利点: device 側の制御が単純。
- 欠点: 左右で露出・色がばらつき、editor 側に色合わせ処理が必須となる。

### 露出/WB: 常に手動

- 利点: 左右の値を完全に一致させられる。
- 欠点: 撮影のたびに設定が必要で、持ち歩きカメラとしての使い勝手が悪い。

### 露出/WB: 左で AE/AWB → 右へコピー固定（採用）

- 利点: 自動露出の手軽さを保ちつつ、左右の露出・ゲイン・色補正値を一致させられる。
- 欠点: 個体差（センサー感度・色）は値のコピーでは吸収できない。

## 結果 / 影響

- 基板改造なしで、左右の同期と露出/WB の一致を実現できる。
- ハードウェア同期ほどの厳密さは得られないトレードオフを受け入れる。meta.json に記録した左右差で影響を検出する。
- 個体差による色のずれは残りうる。後続マイルストーン候補として「色合わせ強化」と「ハードウェア同期（XVS）」を挙げておく。
