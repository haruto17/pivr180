# 0011. AOA でつないだ Android アプリからカメラを操作する

## ステータス

承認

## コンテキスト

外出先では、撮影の前にプレビューで構図を確かめ、撮影した後に撮影できたか（左右とも写っているか、エラーが起きていないか）を確かめたい。[0001](./0001-record-on-pi-process-on-mac.md) では、現場での確認をスマホ Web UI の左右並びのライブプレビューと撮影一覧で補うとした。[0009](./0009-web-ui-in-capture-process-on-port-80.md) でスマホ Web UI を撮影ソフトと同じプロセスで配信すると決め、外出先では Pi の Wi-Fi アクセスポイントにスマホをつなぐ計画だった。

2026-11-24〜25 に、スマホから Pi につなぐ方式を実機で試した（[0010](./0010-spi-display-for-last-capture-and-status.md) のコンテキスト）。

- **Pi の Wi-Fi アクセスポイント**: Android の接続が Pi まで届かなかった。PMF の設定を変えても直らなかった。
- **有線の直結**（Pi 5 の `eth0`）: 接続できるときとできないときがあった（#116、#117）。
- **Bluetooth で縮小画像を送る**（#118）: 手間が大きい。

その結果、0010 で SPI ディスプレイ Adafruit 4313 に撮影結果を表示すると決めた（#119、#120）。しかし、ディスプレイではライブプレビューも操作もできない。オーナーはディスプレイをやめ、Android スマホを USB でつなぎ、Android Open Accessory（AOA）でアプリから操作する方式にすると決めた（#119、#120 は not planned でクローズした）。

AOA では、USB のホスト側（Pi）が制御要求でスマホをアクセサリモードに切り替え、その後はバルク転送でやり取りする。ネットワークを使わないため、Wi-Fi の相性やモバイル通信の問題がない。

## 決定

- **接続**: Pi 5 の USB-A をホスト、Android スマホをアクセサリとし、AOA でつなぐ。スマホは Pi から給電される。USB-A の出力は合計 600mA に制限される場合があり（[0006](./0006-usb-c-pd-power-bank.md)）、その枠を AtomS3 Lite と分け合う。
- **アプリの機能**:
  - ライブプレビュー: 左右を並べた 640x480×2 の映像を、JPEG 品質 70、最大 5fps で送る。撮影中も止めない。
  - シャッター
  - 撮影設定: 露出補正、ホワイトバランス、コントラストを変更する。
  - 撮影一覧: サムネイル付きで表示し、削除する。
  - シャットダウン
  - 状態表示: 直前の撮影の左右のサムネイル、待機中・撮影中・エラーとその内容、撮影枚数、空き容量、同期の警告を表示する。
- **Pi 側**:
  - 撮影ソフト `pivr180-capture` のプロセス内のスレッドで AOA を扱う。0009 の uvicorn のスレッドを置き換える。
  - アプリからのシャッターは、`ButtonShutter` と同じく、キューで撮影のトリガーに合流させる。
  - USB は pyusb で扱う。root でないユーザーで動く撮影ソフトが USB にアクセスできるように、udev ルールを用意する。
- **プロトコル**:
  - `schema/` に JSON Schema とメッセージの例を置き、Python と Kotlin のテストで同じ例を読む。定義の食い違いを CI で見つけるため。
  - メッセージは、長さ・種類・本文のフレームにする。制御のメッセージの本文は JSON、画像は JPEG のバイナリにする。
  - 最初のハンドシェイクで、プロトコルのバージョンを伝える。
  - 撮影モードの項目をプロトコルと UI に持つ。今回は写真モードだけを受け付ける。動画は M10 で扱う（#131）。
- **Android アプリ**: `android/` に置く。Kotlin、Jetpack Compose、Gradle（Kotlin DSL）で作り、テストは JUnit、lint は ktlint（または detekt）を使う。minSdk は 31（Android 12）。Play ストアには公開せず、サイドロードで配布する。
- **廃止するもの**: スマホ Web UI（0009）、Wi-Fi アクセスポイント（`pivr180-ap`）、有線の直結（`pivr180-eth-direct`）、SPI ディスプレイ（0010）。Web UI は、アプリで同じことができるようになってから最後に消す。
- **残すもの**: ホスト名 `pivr180.local` と avahi は、editor の取り込み（SSH・rsync）に使うので残す。
- スマホがつながっていないときの状態表示は、AtomS3 Lite の LED だけになる（[0008](./0008-atoms3-lite-usb-shutter-and-status.md)）。
- 手動露出（#132）と撮影設定の保存（#133）は、M4 の後半で扱う。

## 検討した選択肢

### Pi の Wi-Fi アクセスポイントにスマホをつなぐ

- 利点: ケーブルが要らない。スマホ Web UI をそのまま使える。
- 欠点: 実機では、Android の接続が Pi まで届かなかった。PMF の設定を変えても直らなかった。

### 有線の LAN で直結する（#116、#117）

- 利点: スマホ Web UI をそのまま使える。Wi-Fi の相性の問題を避けられる。
- 欠点: 実機では、接続できるときとできないときがあった。Android 用の USB-C の LAN アダプタと LAN ケーブルを持ち歩く必要がある。

### スマホのテザリングに Pi をつなぐ

- 利点: Android 側の接続は安定していると見込める。スマホ Web UI をそのまま使える。
- 欠点: モバイル通信を使う。オーナーが採用しないと決めた。

### USB の MTP でスマホへ画像をコピーする

- 利点: ネットワークを使わない。
- 欠点: つなぐたびにスマホのロックを解除し、ファイル転送を許可する必要がある。Linux の MTP は動作が不安定になりやすい。撮影前のプレビューも操作もできない。

### Bluetooth で縮小画像をスマホへ送る（#118）

- 利点: ネットワークもケーブルも使わない。
- 欠点: ペアリングが必要になる。Android が受信のたびに承認を求める場合がある。Pi 側で送信を担う obexd はユーザーのセッションバスで動くため、systemd のサービスから使うのが難しい。ライブプレビューも操作もできない。

### SPI ディスプレイ Adafruit 4313 で本体に表示する（0010）

- 利点: スマホもネットワークも使わずに、撮影した直後に左右の画像と状態を確かめられる。
- 欠点: ライブプレビューも操作もできない。GPIO の配線と筐体の表示窓が必要になる。オーナーがやめると決めた。

### HTTP を AOA に通し、WebView でスマホ Web UI を使う

- 利点: 既存のスマホ Web UI と Web API をそのまま使える。アプリは AOA と HTTP をつなぐ部分と WebView だけで済む。
- 欠点: オーナーが Web UI を廃止し、アプリはネイティブの UI で作ると決めた。HTTP を AOA の上で中継する仕組みが別に要る。

### AOA でつなぎ、ネイティブの Android アプリと独自のフレームでやり取りする（採用）

- 利点: ネットワークを使わないため、Wi-Fi の相性、デフォルトルート、モバイル通信の問題がない。ケーブル 1 本で通信と給電ができる。ライブプレビュー、操作、撮影結果の確認を 1 つのアプリでできる。ケーブルを挿すとアプリが起動する。プロトコルを `schema/` で共有し、Python と Kotlin のテストで食い違いを見つけられる。
- 欠点: Android アプリという新しいコンポーネントと、そのビルド・テスト・配布を管理する必要がある。ケーブルが必要になる。Android 以外のスマホでは使えない。

## 結果 / 影響

- `android/` を新しいコンポーネントとして追加する。CI に Android のビルド・単体テスト・lint のジョブが加わり、アプリを保守し続ける必要がある。
- 外出先では、スマホと Pi を USB ケーブルでつなぐ必要がある。
- スマホは Pi の USB-A から給電され、600mA の枠を AtomS3 Lite と分け合う。撮影中に電圧が下がって Pi や撮影が止まらないかを、実機で確認する。
- スマホ Web UI がなくなり、device の Python の依存から fastapi と uvicorn が外れる。0009 の 80 番ポートと `CAP_NET_BIND_SERVICE` も要らなくなる。
- Wi-Fi アクセスポイントと有線の直結の設定がなくなる。自宅では、これまでどおり `pivr180.local` に SSH して editor から取り込む。
- ネットワークにつながっていない状態でもカメラの同期が取れるようにする修正（#121）は、この決定とは別に必要になる。AOA はネットワークを使わないため、外出先ではデフォルトルートがない状態で撮影することになる。
- スマホがつながっていないときは、AtomS3 Lite の LED でしか状態が分からない。エラーの内容は、スマホをつなぐか Pi のログで確認する。
- 0010 で一部見直した 0008 の「GPIO は使わない」は、元に戻る。SPI ディスプレイの配線と筐体の表示窓は要らなくなる。
