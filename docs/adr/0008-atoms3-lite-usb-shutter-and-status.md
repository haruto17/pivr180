# 0008. シャッターボタンと状態表示は USB 接続の AtomS3 Lite で行う

## ステータス

承認

## コンテキスト

pivr180 は、スマホを使わずに本体のボタンだけで撮影とシャットダウンができるようにする（[plan.md](../plan.md) の物理 UI、[milestone.md](../milestone.md) の M3）。そのため、シャッターボタンと、待機中・撮影中・エラーといった状態を本体で知らせる手段が必要になる。

当初は GPIO にタクトスイッチと状態 LED をつなぎ、gpiozero で扱う計画だった（#19, #20）。LED が手元になかったため、SPI ディスプレイ Adafruit 4313 で状態を表示する案も検討したが、採用しなかった（#77, #78）。一方で、M5Stack AtomS3 Lite を所有している（#79）。

AtomS3 Lite の仕様は次のとおり（[M5Stack 公式ドキュメント](https://docs.m5stack.com/en/core/AtomS3%20Lite)、SKU: C124）。

- SoC は ESP32-S3FN8（Xtensa LX7 デュアルコア 240MHz）、Flash 8MB
- 本体にプログラムできるボタンと RGB LED（WS2812C-2020）を持つ
- USB Type-C で 5V 給電を受け、同じ端子でプログラムの書き込みとシリアル通信ができる
- 外形 24.0 × 24.0 × 9.5 mm、重さ 5.3g、背面に M2 のネジ穴がある
- 動作温度 0〜40°C

## 決定

- シャッターボタンと状態表示には **AtomS3 Lite** を使う。本体のボタンをシャッターボタンに、RGB LED を状態表示に使う。
- AtomS3 Lite は筐体に固定し、短い USB ケーブルで Pi 5 の USB 端子につなぐ。GPIO は使わない。
- AtomS3 Lite のファームウェアは **PlatformIO ＋ Arduino（C++）** で作り、`firmware/` で管理する。
- Pi と AtomS3 Lite は USB シリアル（CDC）で、1 行 1 メッセージのテキストでやりとりする。メッセージの具体的な書式は、ファームウェアと device のタスクで決めて `firmware/` に文書化する。
  - AtomS3 Lite → Pi は、ボタンの押下と解放だけを送る。3 秒長押しの判定は Pi 側で行う。判定ロジックを Mac 上の pytest で検証できるようにするため。
  - Pi → AtomS3 Lite は、状態（待機中・撮影中・エラー）を送る。AtomS3 Lite が状態を LED の色と点滅に変換する。
  - Pi は状態を一定の間隔で送り直し、これをハートビートとする。
- AtomS3 Lite は、Pi から最初のメッセージを受け取るまで、ファームウェア単体で起動中の表示を行う。メッセージを受け取った後に一定時間メッセージが来なければ、切断の表示にする。シャットダウン後も USB 給電が続く場合に、古い表示を残さないため。
- Pi 側は、AtomS3 Lite のデバイスを `/dev/serial/by-id/` などの名前で固定して開く。

## 検討した選択肢

### GPIO のタクトスイッチと LED（＋抵抗）

- 利点: 部品が安く、gpiozero で扱える。当初の計画をそのまま使える。
- 欠点: LED と抵抗を追加で購入し、配線する必要がある。撮影ソフトが起動するまでは状態を表示できない。

### Pi 5 の基板 LED（ACT/PWR）を `/sys/class/leds` で制御する

- 利点: 状態表示のために部品を追加する必要がない。
- 欠点: `/sys/class/leds` への書き込みに root 権限か udev の設定が必要になる。筐体の内側に隠れるため、ライトパイプが必要になる。2 色しかなく、表せる状態が少ない。シャッターボタンは別に用意する必要がある。

### SPI ディスプレイ Adafruit 4313

- 利点: 手持ちの部品で済む。状態に加えて、エラーの内容を短い文字で表示できる。
- 欠点: SPI0 と DC・RST 用の GPIO を使うため、配線が増える。筐体に表示窓が必要になる。撮影ソフトが起動するまでは何も表示されない。シャッターボタンは別に用意する必要がある。

### AtomS3 Lite を USB 接続する（採用）

- 利点: 手持ちの部品 1 つでシャッターボタンと状態表示を兼ねられ、GPIO の配線が不要になる。RGB LED の色と点滅で状態を区別できる。ファームウェア単体で起動中や切断の表示ができる。
- 欠点: ファームウェアという新しいコンポーネントと、Pi との通信の取り決めを管理する必要がある。Pi の USB 端子と USB ケーブルの取り回しを筐体内に確保する必要がある。エラーの内容は表示できない。

## 結果 / 影響

- GPIO の配線と gpiozero が不要になる。配線図（M8-4）は、AtomS3 Lite の取り付け位置と Pi 5 との USB 接続を扱う。
- `firmware/` を新しいコンポーネントとして追加する。ハードウェアに依存しないロジック（メッセージの解釈、状態と表示の対応、ハートビートのタイムアウト）は PlatformIO の native 環境の単体テストで検証する。
- 筐体は、AtomS3 Lite のボタンを押せて LED が見える位置に、背面の M2 ネジ穴などで固定する必要がある（[0007](./0007-blender-enclosure-fdm-printing.md)）。
- AtomS3 Lite は Pi 5 の USB 端子から給電する。5V/5A を出せない電源では USB 端子の出力が 600mA に制限される（[0006](./0006-usb-c-pd-power-bank.md)）が、MVP で USB につなぐのは AtomS3 Lite だけなので影響は小さい見込み。実機で確認する。
- エラーの内容は本体では表示できない。内容は Pi のログで確認する。
