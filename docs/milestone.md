# milestone.md

[plan.md](./plan.md) の MVP を、次のマイルストーンに分けて進める。各タスクは 1 issue・1 PR で完了できる粒度とする。

- タスクの選び方は [workflow.md](./workflow.md) に従う。
- 「依存」に挙げたタスクが完了するまで、そのタスクには着手しない。
- 期日は GitHub のマイルストーンで設定する。

## 一覧

| # | マイルストーン | 主な対象 | 依存 |
|---|---|---|---|
| M1 | 基盤整備 | 全体 | なし |
| M2 | device: 撮影と保存 | `device/` | M1 |
| M3 | device: 物理 UI・運用 | `device/`, `firmware/` | M2 |
| M4 | device: スマホ Web UI・ネットワーク | `device/` | M2 |
| M5 | editor: 取り込みと一覧 | `editor/` | M1 |
| M6 | editor: 補正と書き出し | `editor/` | M5 |
| M7 | viewer と HTTPS 配信 | `viewer/`, `editor/` | M6 |
| M8 | hardware: 筐体と配線 | `hardware/` | なし |
| M9 | MVP 統合 | 全体 | M3, M4, M7, M8 |

M2〜M4（device）、M5〜M7（editor / viewer）、M8（hardware）は並行して進められる。

## M1: 基盤整備

**ゴール**: 各コンポーネントの開発を始められる状態にする。

| ID | タスク | 依存 |
|---|---|---|
| M1-1 | `device/` を uv で初期化し、pytest が動く状態にする | なし |
| M1-2 | `editor/` を Tauri（Rust ＋ Svelte/TS/Vite, pnpm）で初期化し、`cargo test` と Vitest が動く状態にする | なし |
| M1-3 | `viewer/` を Svelte/TS/Vite ＋ Three.js（pnpm）で初期化し、Vitest が動く状態にする | なし |
| M1-4 | `schema/` に meta.json の JSON Schema を定義する | なし |
| M1-5 | `schema/` に補正値（イメージサークルの中心・半径・回転）の JSON Schema を定義する | なし |
| M1-6 | `hardware/` を作成する | なし |

**完了条件**

- 各ディレクトリにファイルが 1 つ以上あり、各テストコマンドが成功する。
- meta.json と補正値の JSON Schema がある。

## M2: device: 撮影と保存

**ゴール**: Pi 上で左右の画像を同時に撮影し、meta.json とともに保存できる。

| ID | タスク | 依存 |
|---|---|---|
| M2-1 | カメラ制御を抽象化し、Mac 上のテストで使う Fake を用意する | M1-1 |
| M2-2 | Picamera2 で 2 台のカメラを制御する実装を作る（venv は `--system-site-packages`） | M2-1 |
| M2-3 | 左右のフレームをセンサー時刻で組にし、時刻差が 1ms を超えたら最大 3 回撮り直す。3 回とも超えた場合は警告付きで保存する | M2-1 |
| M2-4 | プレビュー中に左カメラの ExposureTime / AnalogueGain / ColourGains を右カメラへコピーし、シャッター時に左右とも固定する | M2-1 |
| M2-5 | 4056×3040・JPEG 品質 100 で `/data/captures/<YYYYMMDD-HHMMSS-NNN>/{left.jpg,right.jpg,meta.json}` に保存する | M2-1, M1-4 |
| M2-6 | meta.json を出力し、JSON Schema で検証するテストを書く | M2-5 |

**完了条件**

- Fake を使った pytest が Mac 上で成功する。
- 実機で撮影すると、左右の JPEG と schema に適合する meta.json が保存される。

## M3: device: 物理 UI・運用

**ゴール**: USB でつないだ AtomS3 Lite のボタンと LED だけで撮影・シャットダウンでき、電源を入れれば撮影できる状態になる。

| ID | タスク | 依存 |
|---|---|---|
| M3-1 | AtomS3 Lite から USB シリアルでボタンの押下・解放を受け取る。押すと撮影し、3 秒長押しで安全にシャットダウンする。長押しの判定は device 側で行う | M2-5, M3-5 |
| M3-2 | AtomS3 Lite へ USB シリアルで状態（待機中・撮影中・エラー）を一定の間隔で送り、LED で表示させる | M2-5, M3-6 |
| M3-3 | 撮影ソフトを systemd で自動起動し、撮影できる状態になったら AtomS3 Lite の LED で知らせる | M3-2 |
| M3-4 | `firmware/` を PlatformIO ＋ Arduino で初期化し、native 環境の単体テストが動く状態にする | なし |
| M3-5 | ファームウェアで、ボタンの押下・解放を USB シリアルで 1 行 1 メッセージのテキストとして送る。メッセージの書式を `firmware/` に文書化する | M3-4 |
| M3-6 | ファームウェアで、受け取った状態を RGB LED の色と点滅で表示する。最初のメッセージを受け取るまでは起動中を表示し、その後一定時間メッセージが来なければ切断を表示する。メッセージの書式を `firmware/` に文書化する | M3-4 |
| M3-7 | SPI でつないだ Adafruit 4313 に、直前の撮影の左右の縮小画像、状態（待機中・撮影中・エラー）とエラーの内容、撮影枚数、保存先の空き容量を表示する。描画で撮影や保存を止めない | M2-5 |

**完了条件**

- native 環境の単体テストと pytest が Mac 上で成功する。
- 実機で、電源投入 → AtomS3 Lite の LED で起動中・待機を確認 → ボタンで撮影し、ディスプレイに縮小画像と状態が表示される → 長押しでシャットダウン → LED が切断の表示になるか消灯する、の流れができる。

| M4-3 | 露出補正・ホワイトバランス・コントラストを変更する撮影設定画面を作る | M4-1, M2-4 |
| M4-4 | 撮影一覧と手動削除の画面を作る | M4-1, M2-5 |

| ID | タスク | 依存 |
|---|---|---|

## M6: editor: 補正と書き出し

**ゴール**: 魚眼画像を補正し、VR180（SBS 正距円筒 180°）の JPEG を書き出せる。

| ID | タスク | 依存 |
|---|---|---|
| M6-1 | レンズ仕様値（等距離射影、1.45mm、1.55µm）から補正値の初期値を計算する | M1-2, M1-5 |
| M6-2 | 補正値の読み書きを実装する。デバイス既定値を全撮影に使い、撮影ごとの値で上書きできる | M6-1 |
| M6-3 | Rust で LUT を事前計算し、image ＋ rayon で魚眼から正距円筒 180° へ変換する。合成魚眼画像で精度を検証する | M6-1 |
| M6-4 | 左右のイメージサークルの中心・半径・回転を手動で調整する画面を作り、縮小画像を WebGL で変換してプレビューする | M6-2, M5-4 |
| M6-5 | SBS の JPEG を `exports/` に書き出す（片目既定 約 2880×2880、設定で変更可、ファイル名末尾 `_180_LR`） | M6-3, M6-2 |

**完了条件**

- 変換の単体テストが成功する。
- 実機の撮影データから書き出した JPEG を Mac 上で確認し、左右が正しく並んでいる。

## M8: hardware: 筐体と配線

**ゴール**: 部品を収めて持ち歩ける筐体を印刷し、配線を確定する。

| ID | タスク | 依存 |
|---|---|---|
| M8-1 | BOM を `hardware/` にまとめる | M1-6 |
| M8-2 | USB-C PD モバイルバッテリーを選定し、実機で動作を確認する | なし |

**ゴール**: 撮影から Quest 3 での立体視までを、実機で一通り行える。
