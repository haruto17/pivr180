# pivr180 editor

Mac 側エディタ（Tauri ＋ Svelte/TS/Vite）。

## 開発

```sh
pnpm install
pnpm tauri dev
```

## 保存先

既定の保存先は `~/Pictures/pivr180/` で、その下を次のように使い分ける。

- `captures/`: Pi から取り込んだ撮影データ
- `exports/`: 書き出した VR180 データ

保存先は画面の「保存先」欄に絶対パスを入力して「保存」で変更できる。変更時に `captures/` と `exports/` を作成し、設定はアプリ設定ディレクトリの `settings.json` に保存する。

## 撮影一覧

画面の「撮影一覧」欄に `captures/` 内の撮影を新しい順に並べ、撮影ごとに左右のサムネイルを表示する。`left.jpg` と `right.jpg` が揃っていないフォルダは表示しない。「取り込み」が成功すると一覧を自動で取り直す。それ以外で撮影を追加・削除したら「再読み込み」で一覧を取り直す。

サムネイルは長辺 320px に縮小して、アプリのキャッシュディレクトリ（macOS では `~/Library/Caches/com.haruto17.pivr180.editor/`）の `thumbnails/<保存先キー>/<撮影 ID>/{left,right}.jpg` に保存し、元画像が更新されるまで再利用する。保存先キーは captures ディレクトリの絶対パスの FNV-1a 64bit ハッシュ（16 桁の 16 進数）で、別の保存先に同じ撮影 ID があってもサムネイルを取り違えない。`captures/` 内には書き込まない。キャッシュは削除しても次回表示時に作り直される。

## 取り込み

画面の「取り込み」欄の「取り込む」で、Pi の `/data/captures/` にある撮影データを rsync（SSH 経由）で保存先の `captures/` に取り込む。

- 既定の接続先は `pivr180.local`。Pi のユーザー名が Mac と違う場合は `user@pivr180.local` のように入力するか、`~/.ssh/config` に `User` を設定する。接続先は `settings.json` に保存される。
- 取り込み済みのファイルは再取得しない（`rsync -a` で同じファイルは転送されない）。画面には今回取り込んだ撮影データの件数を表示する。
- 既定では Pi 側のデータは取り込み後も削除しない。「取り込み後に Pi から削除する」をオンにすると、今回の取り込みで転送した撮影のうち、次をすべて満たすものだけを Pi の `/data/captures/` から削除する（設定は「取り込む」を押したときに `settings.json` に保存される）。
  - Mac 側に `left.jpg`・`right.jpg`・`meta.json` が揃い、`meta.json` が最後まで書かれている（JSON として読め、末尾が改行で終わる）。撮影中で途中までしか取り込めなかったものは残す。
  - 取り込みの直後にもう一度 rsync を dry-run（`-n`）で実行して、差分が出ない（取り込み中に Pi 側で書き換わったものは残す）。
- 以前の取り込みですでに Mac にある撮影は、オプションをオンにしても削除しない。rsync が失敗したとき、確認の dry-run が失敗したときは何も削除しない。削除は 100 件ずつ ssh で行い、途中で失敗したときは、それまでに削除した件数とエラーを画面に表示する。
- パスワード入力は求めない（`BatchMode=yes`）ので、事前に SSH 鍵認証を設定しておく。初回はホスト鍵の登録も兼ねて次を実行する。

```sh
ssh-copy-id <user>@pivr180.local
ssh <user>@pivr180.local true  # パスワードなしで通ることを確認
```

## 補正値

左右のイメージサークルの補正値（中心・半径・回転）は、保存先の `corrections/` に `schema/correction.schema.json` の形式で保存する。`captures/` 内には書き込まない。

- `corrections/device_default.json`: デバイスの既定値。すべての撮影に使う。ファイルがなければ、レンズの仕様値から計算した初期値（4056×3040 の中心、半径約 1469.5px、回転 0°）を左右に使う。
- `corrections/captures/<撮影 ID>.json`: 撮影ごとの上書き値。上書きするカメラだけを持ち、持たないカメラはデバイスの既定値を使う（既定値を後から変えると、そのカメラにも反映される）。上書き値を消すと、その撮影は既定値に戻る。両方のカメラを省いた上書き値は保存できない。

保存時は範囲外の値（中心が負、半径が 0 以下、回転が (-180°, 180°] の外）をエラーにする。読み込み時は形式に合わないファイルをエラーにする。

## 補正

撮影一覧の各撮影の「補正」で、その撮影の補正画面を一覧の上に開く（同時に開けるのは 1 撮影だけ。「閉じる」で閉じる）。

- 左右それぞれ、中心 x・中心 y・半径・回転を数値入力とスライダーで変更できる。値は元画像（例: 4056×3040）の画素単位で、スライダーの範囲は中心が元画像の幅・高さまで、半径が長辺まで、回転が -179.9°〜180°。
- 左右それぞれ、その撮影が既定値を使っているか（「既定値を使用」）、撮影ごとの上書き値を持っているか（「この撮影で上書き」）を表示する。
- 縮小した魚眼画像にイメージサークル・中心・上方向（回転を反映）を重ねて表示し、その横に WebGL で正距円筒 180° に変換したプレビューを表示する。どちらも値を変えるたびに描き直す。変換は「変換」の式と同じで、参照元座標を元画像の大きさで正規化して縮小画像を参照する。WebGL を使えない環境では変換プレビューの代わりにメッセージを表示する。
- 縮小画像は長辺 1024px で、サムネイルと同じくキャッシュディレクトリの `previews/<保存先キー>/<撮影 ID>/{left,right}.jpg` に保存し、元画像が更新されるまで再利用する。保存先キーは captures ディレクトリの絶対パスの FNV-1a 64bit ハッシュ（16 桁の 16 進数）で、別の保存先に同じ撮影 ID があっても縮小画像を取り違えない。
- 「この撮影に保存」は左右両方の値をその撮影の上書き値として保存する（変更していない側も上書き値になる）。「既定値として保存」は左右両方の値をデバイスの既定値として保存する。「既定値に戻す」はその撮影の上書き値を消し、既定値を読み込み直す。

## 変換

魚眼画像（等距離射影）を片目ずつ正距円筒 180° に変換する。出力画素ごとの参照元座標を変換テーブル（LUT）として事前に計算し、Rust（`src-tauri/src/equirect.rs`）で画素を並べ替える。補正中の WebGL プレビューも同じ式で変換する。

- 出力は経度 −90°〜+90°（左→右）、緯度 +90°〜−90°（上→下）。出力画素 (i, j)（幅 W・高さ H）は画素中心の角度を使う: λ = −90° + 180°·(i + 0.5)/W、φ = 90° − 180°·(j + 0.5)/H。
- 方向ベクトルは d = (cos φ sin λ, sin φ, cos φ cos λ)（z が光軸、y が上）。
- 光軸からの角度 θ = acos(d.z)、画像上の向き α = atan2(−d.y, d.x)（画像の y は下向き）。
- 等距離射影: r = radius_px · θ / (π/2)（radius_px は画角 180° に対応する半径）。
- 回転: 魚眼画像は表示上で時計回りに rotation_deg だけ回転しているとみなし、α + rotation_deg の向きを参照する。
- 参照元座標は (center_x_px + r·cos(α + rot), center_y_px + r·sin(α + rot))。原点は左上の画素の左上の角で、画素 (x, y) の中心は (x + 0.5, y + 0.5)。
- 参照元座標の周囲 4 画素を双線形補間する。参照元座標が画像の外なら黒にする。画像の内側でも周囲の画素がはみ出す場合は、端の画素で補う。

## 書き出し

撮影一覧の各撮影の「書き出し」で、左右の画像を正距円筒 180° に変換して横に並べた（SBS）JPEG を保存先の `exports/` に書き出す。書き出し中は「書き出し中…」を表示し、終わると書き出したファイルのパス、失敗したときはエラーを表示する。

- 補正値はその撮影の値（撮影ごとの上書き値があればそれ、なければデバイスの既定値）を使う。
- 片目の解像度 N は既定で 2880 で、画面の「書き出し」欄で 256〜8192 の範囲で変更できる（「保存」で `settings.json` に保存）。出力は幅 2N・高さ N で、左半分が左目、右半分が右目。
- ファイル名は `<撮影 ID>_180_LR.jpg`、JPEG の品質は 95。
- 同じ撮影をもう一度書き出すと上書きする。一時ファイルに書き終えてから置き換えるので、書き出しに失敗しても前のファイルは残る。`captures/` 内には書き込まない。
- 書き出しは一度に 1 件ずつ行い、複数の撮影で「書き出し」を押すと順番に処理する。

## viewer 配信

editor の起動時に、HTTPS サーバーをポート 8443（全インターフェース）で起動し、viewer の画面と写真一覧 API を同じオリジンから配信する。Quest 3 のブラウザで `https://<Mac のホスト名>.local:8443/` を開く。

- `GET /api/photos`: 保存先の `exports/` 直下にある `*_180_LR.jpg` の一覧を、新しい順（ファイル名の降順）に `[{"name": "<ファイル名>", "url": "/photos/<ファイル名>"}]` の JSON で返す。`exports/` 以外の写真は返さない。保存先はリクエストごとに `settings.json` から読むので、変更はすぐに反映される。
- `GET /photos/<ファイル名>`: `exports/` 直下の `*_180_LR.jpg` を `image/jpeg` で返す。それ以外（区切り文字を含む名前、存在しないファイルなど）は 404。
- それ以外のパス: viewer の静的ファイル（`/` は `index.html`）。存在しなければ 404。

証明書と秘密鍵は、アプリ設定ディレクトリ（macOS では `~/Library/Application Support/com.haruto17.pivr180.editor/`）の `certs/cert.pem` と `certs/key.pem`（PEM 形式）から読む。

画面の「viewer 配信」欄に、起動できたときは URL（`https://localhost:8443/` と `https://<ホスト名>.local:8443/`）、起動できなかったとき（mkcert がない・失敗した、証明書を読めない、ポートを使えない）はその理由を表示する。原因を取り除いた後は editor を再起動する。

viewer の静的ファイルは `viewer/dist` から読む。リリースビルド（`pnpm tauri build`）は viewer をビルドしてから（`viewer/` で `pnpm install` しておく）バイナリに埋め込む。開発ビルド（`pnpm tauri dev`）は実行時にディスクの `viewer/dist` を読むので、事前に `viewer/` で `pnpm build` しておく（なければ 404 になる）。

### 証明書の発行

editor の起動時に `certs/cert.pem` と `certs/key.pem` の両方があれば、それをそのまま使う（再生成しない）。Quest で警告の承認やルート証明書の導入をやり直さずに済むようにするため。どちらかがなければ、mkcert で次の名前に対して発行し直す。

- `<LocalHostName>.local`（`scutil --get LocalHostName` の値。取れなければホスト名の先頭のラベル）
- Mac の LAN IP（既定の経路で使われるアドレス。ネットワークにつながっていなければ含めない）
- `localhost`

mkcert は PATH、`/opt/homebrew/bin`、`/usr/local/bin` の順に探す。事前に入れて、ローカル CA を作っておく。

```sh
brew install mkcert
mkcert -install
```

次のときは `certs/` を削除してから editor を起動し直し、証明書を発行し直す。発行し直した後は、Quest で警告の承認をやり直す（ルート証明書を導入していれば不要）。

- Mac の LAN IP やホスト名が変わったとき（IP や `.local` 名で開くと警告が出る）
- 証明書の有効期限（発行から約 2 年 3 か月）が切れたとき

```sh
rm -r ~/Library/Application\ Support/com.haruto17.pivr180.editor/certs
```

### Quest 3 から開く

次のいずれかで開く。WebXR は secure context でしか使えないため、HTTP では開けない。

#### 警告を承認して開く

1. Quest 3 と Mac を同じ LAN につなぐ。
2. Quest 3 のブラウザで、「viewer 配信」欄の `https://<ホスト名>.local:8443/`（名前を解決できなければ `https://<Mac の LAN IP>:8443/`）を開く。
3. 証明書の警告が出たら「詳細」を開き、そのサイトへ進む。証明書が変わらない限り、承認は一度でよい。

#### ADB でルート証明書を導入して開く

mkcert のルート証明書を Quest 3 に入れると、警告が出なくなる。

1. Meta Horizon アプリで Quest 3 の開発者モードを有効にし、USB で Mac とつないで USB デバッグを許可する（`adb devices` に表示される）。
2. ルート証明書を Quest 3 に送る。

   ```sh
   adb push "$(mkcert -CAROOT)/rootCA.pem" /sdcard/Download/pivr180-rootCA.crt
   ```

3. Android の設定画面を開く。

   ```sh
   adb shell am start -a android.settings.SECURITY_SETTINGS
   ```

4. Quest 3 の画面で「暗号化と認証情報」→「証明書のインストール」→「CA 証明書」を選び、`Download/pivr180-rootCA.crt` を選ぶ（画面ロックの設定を求められたら設定する）。
5. ブラウザを開き直し、`https://<ホスト名>.local:8443/` を開く。警告が出る場合は、上の「警告を承認して開く」で開く。

`mkcert -CAROOT` のディレクトリにある `rootCA-key.pem` は CA の秘密鍵なので、Quest 3 を含め、どこにも送らない。

#### ADB ポート転送で開く

`.local` 名を解決できないとき、または LAN を使えないときは、USB でつないだ Quest 3 の `localhost:8443` を Mac に転送する。LAN IP が変わっても使える。

1. 上の手順 1 と同じく、USB デバッグを許可した状態でつなぐ。
2. ポートを転送する（USB を抜くと解除される）。

   ```sh
   adb reverse tcp:8443 tcp:8443
   ```

3. Quest 3 のブラウザで `https://localhost:8443/` を開く。ルート証明書を導入していなければ、警告を承認する。
